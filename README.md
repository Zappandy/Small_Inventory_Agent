# Kirana AI × Dukaan Saathi

A phone-friendly inventory copilot for small Indian kirana stores. The UI is a hand-rolled HTML/CSS/JS frontend served through Gradio's `gr.Server` (FastAPI) engine. The backend is Dukaan Saathi's ledger-backed SQLite store with a LangGraph agent for analysis and a Modal-hosted vision model for receipt OCR.

## What it does

- **Dashboard** — KPIs, low-stock list, AI-generated reorder suggestions, expiry warnings, festival/seasonal context.
- **Inventory** — search, filter, edit stock counts, record sales, delete products. All stock writes flow through an append-only `stock_ledger` (Dukaan Saathi's safety model).
- **Orders** — pending / approved / rejected restock orders generated by the analysis pipeline. Owner approves before anything ships.
- **Add stock** — three input methods on one screen:
  - **Manual form** — type product details.
  - **Photo** — upload a supplier receipt/invoice; the Modal vision endpoint extracts rows; you approve each row to add or top up stock.
  - **Voice / text command** — say "20 kg toor dal arrived" (English or Telugu code-mixed); the agent parses intent and applies if confident.
- **Seasonal** — upcoming festivals from the Telugu calendar and demand multipliers per category.
- **Settings** — shop name, owner, region, low-stock window, expiry warn days.

## Quick start

Requires Python 3.13+ and [`uv`](https://github.com/astral-sh/uv).

```bash
cd Small_Inventory_Agent
uv sync                          # install dependencies
uv run python app.py             # launches on http://localhost:7860
```

First launch seeds a small demo catalog (Bingo, Coca-Cola, Lay's, Parle, etc.) into `data/dukaan.db`.

## Environment variables (optional)

| Variable                  | What it enables                                  |
|---------------------------|--------------------------------------------------|
| `MODAL_RECEIPT_ENDPOINT`  | URL of the Modal MiniCPM-V endpoint for receipt OCR. Without this, the photo upload tab still loads but returns "endpoint not connected". |
| `MODAL_SPEECH_ENDPOINT`   | URL of the Modal distil-Whisper endpoint for audio transcription (used by the voice tab when wired). |

Set them inline:

```bash
MODAL_RECEIPT_ENDPOINT="https://your-modal-app--receipt.modal.run" \
  uv run python app.py
```

## How the pieces fit

```
┌──────────────────┐    fetch    ┌──────────────────────┐
│ static/app.js    │ ──────────► │ /api/dispatch        │  (JSON in/out)
│ + Jinja2 HTML    │ ◄────────── │ /api/photo           │  (multipart)
└──────────────────┘             └──────────┬───────────┘
                                            │
                          ┌─────────────────┼─────────────────┐
                          ▼                 ▼                 ▼
                    kirana_db.py     agent/graph.py    dukaan_saathi/
                    (adapter)        (LangGraph)        integrations/
                          │                 │           modal_receipt
                          ▼                 ▼                 │
                    dukaan_saathi/storage.py  ◄───────────────┘
                    (SQLite + immutable stock_ledger)
```

- `kirana_db.py` adapts Dukaan Saathi's ledger schema to the column/table shape the kirana-ai UI expects. Every stock write still calls `apply_stock_delta` / `set_product_stock`, so model output never writes inventory directly — the owner always approves.
- `agent/graph.py` runs the analysis pipeline: load → seasonal context → inventory analysis → expiry advice → generate orders. A separate branch handles voice/text command parsing.
- `dukaan_saathi/integrations/modal_receipt.py` POSTs the uploaded image to Modal, then runs `parse_receipt_text` on the returned OCR string to produce structured rows.

## Day-to-day flows

### Add stock from a supplier invoice photo

1. Go to **Add → Photo**.
2. Drop the receipt image. The app uploads it to the Modal endpoint and shows the parsed rows in a table.
3. Each row shows: matched product (or raw text if unmatched), quantity, unit price, total, confidence.
4. Click **Apply** on each row you trust:
   - Matched rows top up existing stock through the ledger.
   - Unmatched rows create a new product seeded with the receipt's quantity and unit price.

### Run analysis and generate reorders

1. Dashboard → **Run AI analysis**.
2. The LangGraph pipeline writes AI inventory/seasonal/expiry insights into the dashboard and inserts pending reorder rows into the `orders` table.
3. Open **Orders → Pending** to approve or reject each suggestion.

### Voice / text command

1. **Add → Voice**.
2. Type or speak (e.g. `"add 5 kg sugar arrived"` or `"కందిపప్పు ఇరవై కేజీలు వచ్చింది"`).
3. The agent extracts action + product + quantity. If the product matches the catalog and confidence is medium+, the stock delta is applied automatically; otherwise the parsed result is shown for review.

## Hugging Face Spaces deployment

The repo is configured for Spaces (see frontmatter above). To deploy:

1. Create a new Space → Gradio SDK.
2. Push this directory as the Space repo.
3. In **Settings → Variables**, add `MODAL_RECEIPT_ENDPOINT` (and `MODAL_SPEECH_ENDPOINT` if you wire audio).
4. The Space starts with `python app.py`, which calls `gr.Server.launch()` and serves the custom HTML UI on port 7860.

The custom frontend qualifies for the hackathon's **Off-Brand** bonus (`gr.Server` with a non-default Gradio look).

## Troubleshooting

- **`ModuleNotFoundError: gradio`** — run via `uv run python app.py`, not bare `python`. `uv sync` installs into `.venv` and `uv run` uses it.
- **Photo upload says "endpoint is not connected"** — `MODAL_RECEIPT_ENDPOINT` is not set, or the Modal app is paused.
- **Analysis returns no orders** — seeded demo stock is already above threshold for some items. Record a few sales (Inventory → row → Sell) to drive items below `min_stock`, then re-run analysis.
- **Fresh DB** — delete `data/dukaan.db` and restart; the schema and demo seed are recreated on next launch.
